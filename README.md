# 晋阳的同人库

一个纯前端 SillyTavern 扩展。它会读取当前角色卡、聊天上下文以及实际启用的世界书条目，为人物、地点、物品、能力、组织、事件和世界规则分别建立原著基线，并把当前 AU 状态持久同步到角色绑定的世界书。

正常生成会立即放行，生成前只从本地选取当前场景和本轮相关的已核实档案，不调用分析或搜索 API，也不会把资料表当成登场清单或剧情提纲。候选译名只作为线索，搜索结果可以校正正式名称、实体类型和所属作品。已有对象直接复用缓存，未知对象在生成后的一次合并分析中被识别并于后台补齐，资料完成且该回复仍是最新回复时会再审核一次。

配置并选择独立分析 API 后，每次正文生成完毕，插件会在后台用一次分析请求同时更新场景状态与执行 OOC 审核。选择“当前酒馆模型”时只允许明确点击的手动识别/核验，正常消息事件不会调用它；手动任务未结束时，插件会阻止新的正文生成并明确提示，避免不可取消的旧请求与主模型并发、争用限额或产生延迟 429。自动识别的“当前人物/地点”是当前场景快照：人物进场时增加，明确离场或切换场景后移除；用户手动添加的固定项始终保留。离场人物的原作档案不会删除，只是不再列为当前在场，日后回归可以直接复用。作品、时间线和时间节点只在正文或用户指令明确发生切换时替换，分析模型不得自行推进剧情；回忆、档案、录像、梦境和假设中的时间不会覆盖当前节点。

当前场景会写入一个独立、常驻且覆盖更新的世界书条目，包含当前作品、时间线、在场人物、地点和已发生状态；它与按实体分别保存的原著基线互不混合。消息接收、渲染、停止、重 Roll、切换 swipe 和编辑只用于同一条按消息单飞的版本队列中作废过时任务；插件绝不会点击、触发或排队重 Roll。过时版本与停止后的半截正文不会落库。世界书保存后会绕过缓存从磁盘复读校验，校验通过才显示同步成功。

插件维护的世界书条目会保持启用：当前场景按当前角色卡常驻生效，各实体档案按名称和别名选择性触发。每次生成前，插件会在本地模拟本轮世界书激活结果；已经由酒馆原生注入且内容为最新版本的条目不会再写入扩展提示，插件只补充未触发、尚未落盘或保存待修复的相关资料。因此世界书本身可以作为插件停用或异常时的持久兜底，同时正常运行时不会重复占用两份 token。这个预检不调用分析模型或搜索 API。

插件会结构化保存所有有明确依据、且影响后续写作的原著差异。每项事实都有唯一归属对象、实体类型、属性键、原著状态、当前状态、证据来源与替换关系；同一属性继续变化时旧状态进入历史，不再与新状态同时生效。角色卡、用户、实际启用世界书和已经明确发生的剧情事件可以建立 AU；助手一次静态写错不能被“洗成设定”。数据库与世界书不限制后续增长，但每轮只投影当前相关的有效事实，节省 token 和时间。

世界书来源会保存具体书名、条目 UID 和内容版本。条目仍启用但本轮关键词没有触发时，其既有设定不会被误删；条目真正关闭、删除或改掉原依据时，相关旧 AU 会在下一次正文生成前撤回，并同步清理插件维护的世界书内容。插件仍只读取 SillyTavern 本轮实际启用的条目，不会扫描同一本书里关闭的其他卡条目。

若正文含有 `NE-BANNER` 场景横幅，插件会把横幅中的人物、地点和时段作为已生成正文的确定事实，覆盖分析模型残留的上一场景候选项；横幅不会被当作原作资料，也不会自行推进剧情。

用户人物和明确标记的原创人物不会通过原作档案别名进行映射。若旧版本曾把用户名字误收进某个原作角色的别名，插件会在场景同步时自动清除并更新对应世界书关键词。

新原作实体第一次实际出现在正文后，插件会按类型在后台检索并建立独立档案。每轮实际查询对象严格不超过“每次最多查询数”，超出的对象保持待补状态，在后续剧情轮次增量处理，不会在同一轮连续发出多批请求。资料写入后，只有在该回复仍是当前最新回复时才会再次审核，避免用户已经继续剧情后悄悄改写历史消息。

缺少 `isOriginal` 判断的新名字按未知/原创安全处理：可以留在当前场景，但在身份得到明确确认前不会外搜或建立原作档案。自定义搜索 AI 在 JSON 中自行写出的 URL 只算线索；严格模式只有服务端搜索工具返回的引用元数据，或插件实际读取的 Wiki/网页结果，才能把资料提升为已验证来源。

手动核验不会对同一轮上下文重复规划联网检索；重试或重生成得到新正文后，只重新计算生成后的当前场景快照与 OOC 审核，不会在正文生成前增加等待。

“重置本局全部资料”只清理当前角色卡的当前聊天、插件世界书条目和运行时注入，不会清空其他角色卡资料或共享搜索缓存；全局缓存由独立的“清空缓存”按钮管理。

独立分析 API 可用时，正文生成完毕后插件用一次分析请求同时提取当前场景、实际涉及的原作对象、AU 候选和事实冲突。人物会核对姓名、外貌、性格、经历、关系与能力；地点、物品、能力、组织、事件和世界规则会核对名称、外观、归属、机制、限制与当前状态。程序先做最短片段修订，再按最终正文更新资料，绝不改变剧情走向、登场对象、行动结果或场景顺序。

已有对象不会重复搜索。新 AU 状态按对象和属性增量更新；只有新对象或明确跨越重大原作节点时才后台联网，且世界书内容逐字段确认变化并通过磁盘复核后才会写入。

免费 Wiki 模式会先把分析模型产生的长检索词压缩为“人物/实体 + 作品名”，空结果不会缓存，避免一次临时失败造成长时间无法重试。

界面会根据当前视口和输入设备自动适配：桌面保持多列宽屏布局，手机竖屏切换为单列触控布局，手机横屏和平板使用双列紧凑布局，并兼容安全区域与动态视口高度。

## 安装

1. 打开 SillyTavern 的“扩展”面板。
2. 点击“安装扩展”。
3. 粘贴本仓库的 Git URL 并安装。
4. 刷新页面，从输入框旁的扩展菜单打开“晋阳的同人库”。

安装地址：`https://github.com/jiny75559-gif/-.git`

仓库根目录就是扩展目录，无需修改 SillyTavern 服务端源码。

## 每位用户独立配置 API

- Wiki 模式免费且无需 Key。
- Tavily、Serper、SerpApi 使用 SillyTavern 自带的用户密钥库。
- 自定义搜索 AI（Grok、OpenAI 兼容中转等）和独立分析 LLM 的 Key 只保存在当前浏览器的 `localStorage`，并按 SillyTavern 用户账号隔离。
- Key 不会写入角色卡、世界书、聊天、扩展设置或 Git 仓库。
- 换手机、电脑或浏览器后，需要在新设备重新填写 Key。

## 自定义 API 要求

自定义 API 应兼容以下端点：

- `GET /v1/models`
- 分析：`POST /v1/chat/completions`
- 联网搜索：`POST /v1/responses` 并支持 `web_search`，或提供自身具备联网能力的 `POST /v1/chat/completions`

模型列表读取会先由浏览器直连，跨域失败时再通过 SillyTavern 通用代理读取。分析请求与 Chat Completions 搜索固定只经酒馆同源代理发送一次 POST，不会在浏览器直连失败后重复提交上游请求。Responses API 联网搜索必须使用 HTTPS 并允许浏览器跨域访问（CORS），不会自动改走另一种联网协议。

## 隐私与安全

浏览器本地存储可防止 Key 被发布或混入酒馆数据，但同源网页脚本理论上能够访问它。请只安装可信的 SillyTavern 扩展，使用权限受限的独立 Key，并定期轮换。设置页提供“删除此设备 Key”按钮。

## 更新

扩展启用了 `auto_update`。通过 Git URL 安装后，可以使用 SillyTavern 的扩展更新功能获取新版本。

每次版本更新后，酒馆会自动弹出一次本版更新内容；插件设置页顶部也会常驻显示当前版本日志。完整历史见 [CHANGELOG.md](CHANGELOG.md)。
